## Source-of-truth hierarchy

2. Latest decisions explicitly confirmed by the Founder.
3. Latest approved project knowledge files.
4. Relevant operational and role documents.
5. Historical conversations and context.

If two sources conflict, record the conflict, compare dates and approval status, and follow the latest confirmed Founder decision. If unresolved and material, stop and ask.

## Update discipline
- Record only explicit Founder decisions as CONFIRMED.
- Keep proposals and hypotheses separate.
- Never silently overwrite an approved decision; mark the old entry OUTDATED and link the superseding entry.
- Every material change needs a dated revision-history entry in the affected file.
- GitHub is the version history/backup. Project Sources must be updated separately when the Founder wants the files available there; a GitHub commit does not prove Project Sources synchronisation.
